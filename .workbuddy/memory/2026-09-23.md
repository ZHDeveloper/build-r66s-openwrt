## 仓库精简为 R66S 专用编译（已完成并推送到 main 分支）

- 用户要求：只编译 FastRhino R66S（RK3568, rockchip/armv8）的 LEDE 和 ImmortalWrt 固件，文件名规范化，新建 main 分支提交。
- 关键事实：
  - R66S 设备名在两源不同：ImmortalWrt `lunzn_fastrhino-r66s`（openwrt-25.12 分支/master 均有）；LEDE master `fastrhino_r66s`。均自带 kmod-r8125。
  - R66S 无 WiFi、无 SATA/NVMe 槽，有 2x USB3.0 + 16GB eMMC；rootfs PARTSIZE 设 1024。
- 改动：
  - 重命名：`lean.sh`→`lede.sh`，`immwrt.sh`→`immortalwrt.sh`；配置 → `configs/lede-r66s.config`、`configs/immortalwrt-r66s.config`；工作流 → `build-r66s-openwrt.yml`。
  - ImmortalWrt 改用官方仓库 openwrt-25.12 分支（旧 ipq60xx 工作流会 sed 成 VIKINGYFY fork，那是给京东云/ipq60xx 设备用的，R66S 不需要）。
  - 删除 x86-64 / armv8(晶晨) / ipq60xx(京东云) 全部配置与工作流、packaging-armv8。
  - 脚本移除：晶晨宝盒(amlogic)、qca-nss-drv/pbuf（ipq60xx 专属）、nlbwmon 菜单调整。
  - 配置：代理插件 immwrt 用 homeproxy+openclash，lede 用 ssr-plus+openclash（lede 无 homeproxy）。
  - `auto-trigger-workflows.yml` 矩阵改为 source: [immortalwrt, lede] → build-r66s-openwrt.yml。
- 提交 `3c8ab21` 已推送至 origin/main（默认代理当时对 github.com 可用）。
- 注意：仓库默认分支仍是 master，GitHub Actions 页面需选 main 分支触发；建议在 GitHub 设置里把默认分支切到 main。
